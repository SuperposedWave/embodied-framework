2026-10-19 · 工作分支 feat/massworld-integration · 实施基线 6dacc21c255e。只交付本地桥接，不宣布整仓合并、真实任务成功或阶段验收通过。

现在已经能做什么

MassWorld 的单任务入口已经能够选择 EmbodiedEval 执行整场评测；机器人每一步怎样取图、推理、执行、计数和评分，仍由原来的 0.3 执行器负责。本轮执行证据是合成任务和已有真实数据的只读复查，没有新增真实模型推理。

原有515项无回归，新增26项桥接测试通过。两套入口的五组命令退出码均为0/0/0/1/2。MassWorld原版和补丁版的全量测试结果一致；其中受客户端依赖影响的用例另在兼容环境补查。不能说MassWorld全部用例在同一个环境里全绿。

两套框架现在怎样接起来

MassWorld 单任务命令／计划／证据
    ↓ 选择 execution backend（整任务执行后端）
massworld-embodied 通用桥接包
    ↓ 传入原样的 0.3 运行配置
EmbodiedEval 0.3 Runner（唯一机器人执行循环）
    ↓ 独立模型 Adapter ↔ 公共空间 ↔ 独立环境 Adapter
原有模型推理环境／仿真环境
    ↓ 原始指标、错误、计数、文件证据
MassWorld result.json 与 scorecard.json

Adapter是只处理模型侧或环境侧转换的适配器。M+N指M个模型、N个环境各自维护适配器；本次没有为每个模型与环境组合新增一套Python类。公共空间仍使用0.3字段，例如head总览视角、左右腕视角、状态来源以及xyzw四元数；xyzw就是x、y、z三个向量分量在前，实数w在后。本轮不改变这些定义。

MassWorld外层只执行一个stage，即一项完整工作，不把它当成一次机器人动作。这里没有嵌套第二个机器人循环，也没有把模型的resize、归一化、控制器或评分搬到桥接包。

结果有没有被改意思

没有。框架执行完成与任务成功是两回事：机器人走完预算而没有完成任务，外层的框架success可以是true，但样本里的官方success仍是false，并明确说明两者含义。评分报错会让外层失败，原指标保留null、valid=false和不可用原因，不填0。

MassWorld的总指标字典只接受数字，因此桥接只投影有效数字；布尔值、空值、单位、来源、错误和完整执行计数都留在result.json的samples及backend-result.json里。所谓“投影”就是从完整原始结果中挑选允许展示的数字，不修改原始结果。

动作次数、真实物理步数、仿真秒数及模型前向次数分别保留。执行失联时保留状态未知；没有拿到完整回执的启动异常也不会猜成状态已知。失败后未尝试的任务另列清单。

每次运行必须使用新目录，原目录存在即拒绝。外层stage缓存关闭、resume关闭、历史复用关闭、尝试次数固定为1。模型内部原有动作缓存不关闭，因此原先每三步推理一次等行为保持原样。manifest与summary文件使用完整SHA256摘要，不以大小和修改时间代替。

结构、资产与运行就绪分开

catalog就是可用组件目录；entry point是Python安装包声明的发现入口，本轮新增组名worldevalkit.execution_backends，插件名embodied-v03。目录直接读取现有注册表，真实模型仍是OpenWAM、openpi、LingBot-VLA、Cosmos3、DreamZero五类，环境仍是LIBERO、VLABench、RoboTwin、DROID仿真、RoboDojo五类；另有明确标注的合成组件。目录列出不代表DreamZero真实推理已通过。

plan和doctor不会创建模型或环境工厂。plan保存结构、公共输入路径、独立来源和资产检查；缺输入或动作不匹配就拒绝。路径和哈希核对完成但运行依赖未核实，状态仍为needs_setup，意思是还不能宣称运行准备充分。首版setup只核验，不安装环境、下载资产或申请GPU。

run在明确提交的本地配置下调用原Runner；是否加--preflight可由调用者选择。没有接入MassWorld的suite矩阵和离线infer/judge分段入口；这些入口仍沿用其原有行为。平台资源调度也不在本轮实现。

环境处理与保留的缺口

当前轻量环境新增PyAV 16.1.0和safetensors 0.7.0，仅用于视频解码及小张量文件测试。未安装新的GPU模型依赖，未下载权重，未改共享驱动或既有原生推理环境。下载命令只在当前进程去掉代理变量；全局代理不变，未使用或保存API密钥。

openpi-client要求NumPy小于2，与当前Python 3.13轻量环境不匹配；没有强行忽略依赖约束或降级NumPy，而是创建隔离Python 3.11客户端测试环境。版本清单见补查回执。原版与补丁版的相关用例都在这个环境复查。

主环境仍有10项明确跳过：8项DROID客户端／文件协议用例由上述兼容环境补查；2项LingBot-World可选推理依赖相关测试仍未执行，不能算通过。它们不是本项目已适配的LingBot-VLA，也不抵扣暂缓的LingBot-VA。

原有严格原生复现差异、全任务多种子统计、DreamZero双H10080GB、正式阶段4接受和契约冻结仍未关闭。本轮没有新增GPU利用率统计，不把既有占卡负载计入评测工作量，也不声称达成新的20%实测窗口。

怎样接入和复跑

以下命令在EmbodiedEval项目根目录执行。先用prepare_workspace.py从已提供的固定ZIP创建全新的测试副本；不要对只读上游就地打补丁。脚本拒绝不同摘要的ZIP、重复路径、符号链接、路径穿越和覆盖旧目录。完整ZIP摘要为e64747418982c8787645925b86f78f120024bea3fbe1dc84496e3ac80966034a。

.venv/bin/python integrations/massworld/prepare_workspace.py   --archive "/path/to/MassWorld-main (1).zip"   --output outputs/massworld-workspace-new

# 当前轻量环境已具备基础依赖；只安装本地两个包，不递归下载依赖
.venv/bin/python -m pip install --no-deps --no-build-isolation   -e outputs/massworld-workspace-new/WorldEvalKit -e integrations/massworld

.venv/bin/python -m worldevalkit.cli catalog backend   --execution-backend embodied-v03

.venv/bin/python -m worldevalkit.cli plan   --execution-backend embodied-v03   --backend-config examples/synthetic_single_run.json   --output-dir outputs/my-massworld-check

.venv/bin/python -m worldevalkit.cli run   --execution-backend embodied-v03   --backend-config examples/synthetic_single_run.json   --output-dir outputs/my-massworld-run

backend-config就是原来的0.3运行配置，不新建逐对接线文件。模型配置、环境配置、种子、预算和控制模式各保留原义；不允许同时再传MassWorld旧--model、--benchmark、--endpoint或另一份参数覆盖，避免两套设置相互打架。--no-cache在该后端下并非必要，因为外层缓存始终禁用。

后端接口约定：catalog读取独立组件目录；preflight只读检查配置；execute接收一个尚不存在的输出目录并完整运行一次。它返回success、execution_state_known、numeric_metrics、samples、metadata、evidence。这里success只表示框架完成；execution_state_known表示执行状态是否已核实；numeric_metrics是可展示的有效数字；samples是完整逐任务结果；metadata保留来源；evidence是带摘要的文件证据。

下一步与验收边界

  1. 先确认本地桥接的软件交付，再选择已有资产上的有限步真实链路，经MassWorld入口运行并与同条件直接入口比较；重新推理随机性、映射正确性与任务成功分别报告。
  2. 真实对照通过后再评审单仓目录迁移，保留Git历史、包名、原生子进程模块路径和历史结果路径；本轮不先搬目录。
  3. 再扩展suite目录／结果汇总和启智执行提供者；启智CLI已经可用不等于提供者已实现，不自动提交任务、申请GPU或启用平台故障重试。
