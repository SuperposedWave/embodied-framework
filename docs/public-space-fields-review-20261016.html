先说结论

你的理解是对的。环境 Adapter 应把自己的相机、状态和执行接口翻译成固定公共格式；模型 Adapter 只认这个公共格式，再翻译成权重所需的格式。普通组合不应要求用户再逐对填写“环境字段 → 模型字段”的接线表。

建议新增 0.3 通路：这个版本号表示“统一公共名称和语义的新消息格式”。保留 0.1、0.2 的行为、配置和历史证据。独立 Adapter 架构已经存在，本轮要补的是公共字段命名及物理含义的一致性，不是再写一套模型与环境成对的 Adapter。

本方案的公共层由四部分组成：空间说明书定义字段含义；公共观测携带本次实际数据；公共动作表达要控制谁、如何控制；任务与结果记录公开指令、预算、计数及评分。不是把所有信息塞进一个固定长度数组。

本文里的英文名称都是拟采用的字段名，旁边均解释具体含义。sensors.head 读作“公共观测的 sensors 相机表里的 head 视角”；点号表示取下一层字段，不是另一套协议。必填指消息或声明必须包含；可选指有可靠数据才提供；预留指只约定语义，不代表本轮新增采集或执行能力。

本轮已做：只读盘点 11 个具名模型输入输出配置、7 个环境协议声明和 23 份源码／证据摘要，未启动模型、仿真或下载。尚未做：修改运行代码、公共契约或迁移旧配置。完整盘点见当前字段、模型能力、环境空间与源码 SHA256 清单。SHA256 是文件内容指纹，用于确认讨论基于哪份文件，不是模型成绩。

现状具体证据需要改成什么

谁负责哪一段

环境原始数据
  → 环境 Adapter：原生名称、单位、四元数 → 公共字段
  → 公共观测：统一名称 + 数值 + 时间 + 真实来源
  → 模型 Adapter：公共字段 → 原生输入、归一化、缓存、推理
  → 模型 Adapter：原生输出 → 公共类型化动作
  → 环境 Adapter：公共动作 → 原生控制器、逆运动学、仿真
  → 公开执行反馈与独立评分结果

逆运动学是“根据末端目标位置求各关节该转多少”，属于环境 Adapter。Runner 是通用调度循环，只管调用顺序、校验、预算、计数和证据；不负责缩图、补相机、四元数纠错、坐标标定或机器人控制。

放在哪里应该包含禁止包含
环境具名协议原生相机对应哪个公共角色；真实测量来源；关节顺序；坐标与控制器；初始化和官方评分。根据当前模型名称改变相机含义、控制规则或评分。
模型具名输入输出配置这个权重需要哪些公共字段；如何缩图、排列、归一化；训练沿用的特殊编码；动作解码与缓存。检查 Benchmark 名称或接收环境对象后再选实现。
公共声明与通用预检查检查字段、单位、维数、时间、参考点、坐标路径、动作类型和完整目标。猜缺失的相机、把 6 关节补成 7 关节、把夹爪目标当测量、编造工具偏移。
普通运行配置模型配置、环境协议、任务／种子／预算、产物位置。必填的逐组合相机重命名表或成对 Python 工厂。

模型配置是“这份权重的说明书”，环境协议是“这版仿真的说明书”。两边分别选择。同一模型可能有不同权重对应不同配置，但不以当前连接哪个环境作为分支条件。

公共消息的完整骨架

每次数据的身份与观测字段

消息／字段人话含义规则与状态
Context.contract_version这条消息按哪版公共规则解释。新通路明确为 0.3；不自动把旧消息当新消息。
run_id / env_id / episode_id / message_id哪次运行、哪个环境实例、哪一局、哪条消息。必填；跨局、旧观测或串错实例的动作拒绝。
Observation.context / observation_id / spec_ref消息身份、本帧编号、适用的空间说明书编号。必填；说明书必须与当前环境一致。
env_step / sim_time_s已经执行几次原生动作、现在的仿真时间。必填；时间单位为秒，不是电脑墙上时钟。
sensors / states相机等传感器数据表／机器人状态数据表。必填容器；只提供声明且真实存在的字段；模型必需字段缺失则拒绝。
public_instruction环境当前公开的任务文字。可选；非空时更新任务文字；不删除原有公开目标图或目标位置。
frame_transforms本次实际获得的动态坐标关系。可为空；每条变换带自己的采集时间，不能假装全部与图像同时采集。
ModelInput只交给模型的公开输入包。保留 context、observation_id、sim_time_s、task_public、sensors、states、state_specs、frame_transforms；拟补充只读 sensor_specs 与 view_aliases，供解释相机角色。公开键名不再改成模型槽名。

模型只看到声明需要的公开数据和解释这些数据所需的公开元数据。不会收到专家动作、隐藏目标状态、成功条件细节或环境实例。复制／筛选数据时仍保持相机字节、状态精度和原采集时间。

空间说明书 SpaceSpec

SpaceSpec 表示“这个环境能够提供和接受什么”，不是本帧数值。下面保留现有字段，并明确拟新增部分。

字段具体内容拟定要求
spec_id / revision公共空间定义编号／固定环境源码版本。必填；变更公共解释必须产生新定义，不能回写历史。
protocol_id / protocol_version环境初始化、控制、计数和评分的具名规则及版本。必填；选择环境规则，不绑定模型。
timing_mode / control_period_s / physics_period_s固定周期或原生变时长；控制周期；物理步周期。时间模式必填；不能用固定控制周期冒充变时长的实际时间。
frames坐标系及已知父子关系。必须含 world；其他只提供有依据的关系。
robots机器人实例、关节、末端和夹爪说明。本轮一个被控实例 robot0，允许单臂或双臂；不扩展多机器人或全身控制。
sensors / state_fields统一传感器定义／统一状态定义。以本文的公共键命名；不能把环境原名留作主键。
view_aliases（新增）例如 main → head：环境协议选定的默认总览视角。可选；只能引用已经存在的公共相机键，不能指向原生字段或形成别名链。
action_specs / controllers实际实现的动作集合／具名原生控制器说明。至少一个执行格式；未实现的类型不能只因公共类型存在就宣称支持。
required_action_targets / action_joint_modes每种执行格式必须同时带上的目标；它支持位置、速度还是力矩。完整目标检查；双臂不得静默只执行一边。
native_protocols原生扩展名称与精确签名。只与同协议执行端匹配，不等于跨环境通用。
contract_version说明书对应的公共版本。新通路 0.3；原 0.2 声明保留。

相机字段如何真正统一

统一相机名与主视角

建议把 head 明确定义为工作区总览视角角色，不是“保证装在物理头部”的承诺。实际固定在场景、装在机身还是腕部，由 mounted_on 单独说明。这样能直接落实你说的“环境写 head，模型取 head”，也不会把场景相机误说成机械臂真的有头。

公共相机键含义不能怎么用
head环境协议指定的工作区总览 RGB 相机。不能因为原生名字含 head 就跳过视角核实；不由此推断安装位置或光轴。
wrist单臂机器人的腕部 RGB 相机。单臂不是“默认左手”；不能为凑双臂同时复制成 left_wrist、right_wrist。
left_wrist / right_wrist双臂机器人真正的左／右腕相机。左右由机器人声明确定，不按图片中物体所在的左右判断。
external_front / external_left / external_right相对机器人底座定义的前／左／右外部相机。必须有安装位置与底座轴向依据；没核实则不凭 cam_1、cam_2 猜左右。
external_0 / external_1外部相机身份明确、方位尚未核实时的稳定编号。编号不声称左右；只接受编号的具名输入配置，不能冒充方向要求已满足。
view_aliases.main“取环境协议的默认主视角”的公共别名，例如指向 head。不是另一张图，不复制载荷；若环境有多个等价候选且未声明默认值，预检查报歧义。

因此：模型明确需要总览 head 就取 sensors.head；模型只要求默认主视角，就让自己的 Adapter 通过公共 main 别名取图。这个默认值在环境协议里定义一次，不为每个模型重写。模型原生变量即使叫 right_wrist，也不表示它实际上一定来自右腕；真实语义在该权重的输入配置中写清楚。

这套名称固定的是角色和来源，不保证不同 Benchmark 的焦距、视角、背景完全相同；这些仍影响权重表现。图像缺失、视角不符合模型明确要求时拒绝，不能用另一张图自动顶替。

每个传感器的说明与实际样本

对象／字段具体含义与约束
SensorSpec.modality / role数据种类／受限公共角色名。RGB 是彩色图像；depth 是深度；point_cloud 是三维点云；audio 是声音；tactile 是触觉。后四类只在可靠采集与模型支持时启用，不是本轮新增能力。
mounted_on / frame_id实际安装对象／传感器坐标系。场景固定相机和腕相机必须区分；相机帧用公共 ID，例如 camera/head，而非照抄环境字段名。
tensor.dtype / shape / layout数值类型／各维大小／排列。RGB 通常 uint8、[高度, 宽度, 3]、HWC；HWC 就是高、宽、通道依次排列。声明的 -1 表示该维接受不同正整数，不是实际图像的负维度。
unit / color_order / available_rate_hz物理单位／色彩通道顺序／可用频率。公共彩色图像采用 RGB；深度若提供则用米。频率未知就不填，不能拿物理步频率冒充出图频率。
native_source（新增来源元数据）原生键名、固定来源版本和提取规则的标识。只供追溯；公共读取路径不得依赖它。
SensorSample.captured_at_s / frame_id该图真正采集时的仿真秒数／该样本的传感器坐标系。
validity / invalid_reason / provenance有效或无效／无效原因／来自传感器。无效图像不能伪造成一张正常的黑图。
payload实际 Tensor 载荷；含 dtype、shape、layout、data 或 data_ref。data 是内联值；data_ref 是外部载荷指针，当前没有读取器，要求真实载荷时仍明确拒绝。
DataRef.storage / key / byte_length / sha256存储类型／定位键／字节数／摘要。只保留现有声明，不借这次字段改造实现文件、共享内存或远程载荷读取。
标定信息相机内参、畸变、外参只有被核实且所需模型使用时才增加具名说明。本文不补造数值。相机坐标统一建议为 x 向右、y 向下、z 向前；需要转换的 Adapter 必须有真实变换依据。

环境输出保持原生图像内容；模型所需 resize（缩放）、裁剪、翻转、归一化、HWC 转其他排列都在模型 Adapter 内完成，且保留来源规则。别名解析不额外取图、不复制另一帧、不提前消费随机数。

机器人状态字段

命名与单双臂规则

继续使用 Observation.states 字典，避免为改名大规模重造层级。单臂直接用下表基础名；双臂加 left_ 或 right_ 前缀。例如 left_joint_positions 就是左臂的实际关节位置。一个字段到底属于谁，由声明中的 robot_id 和 joint_ids / site_id 明确指定。

基础字段名含义／单位可用条件及状态
joint_positions实际机械臂关节位置；转动关节用弧度 rad，移动关节用米 m。不含夹爪；按显式 joint_ids 排列；现有部分环境可提供。
joint_drive_targets给机械臂执行器的关节位置目标。是 controller_target，不是 measurement；不混入夹爪。
joint_velocities / joint_efforts实际关节速度／力矩或推力；rad/s、m/s、Nm 或 N。预留；只有原生接口已可靠提供才启用，不通过差分或零值凭空补齐。
eef_position / eef_quaternion实际末端参考点位置／参考部件方向；米／xyzw 四元数。分别记录 site_id；只有参考点及部件一致或有已知关系时才组成同一个物理位姿。
tcp_position / tcp_quaternion实际工具工作点的位置／方向。可选。TCP 是夹爪中心、吸盘接触点等指定工具参考点；不知道偏移就不能从 eef 猜一个。
gripper_joint_positions夹爪每根指爪关节的实测位置。按夹爪 joint_ids 排列；LIBERO 的两个手指 qpos 属于这里。
gripper_width实际两指间距，单位米。必须有几何和测量依据；不能把两个手指 qpos 简单求和就默认正确。
gripper_open_fraction实际开度，0 是闭合，1 是张开。仅 measurement，需已知测量到开度的规则。RoboTwin 的控制记录不能填这里。
gripper_open_fraction_target夹爪控制目标，0 到 1。controller_target；RoboTwin 截断后的记录和 RoboDojo prev_control 在来源核实后进入这里。
gripper_width_target / gripper_joint_drive_targets / gripper_force_target夹爪目标宽度／各指目标关节值／夹持力目标。可选／预留；分别是米、逐关节单位、牛顿 N；不能跨模式冒充同一开度。
robot_base_position / robot_base_quaternion机器人底座在 world 中的位置／方向。全局字段，不加左右臂前缀；只提供已核实的值，方向未知不能填单位旋转。

所有字段是“允许使用的统一词汇”，不是要求每个环境全部提供。本轮会先迁移已经可靠拥有的数据。一个模型需要的字段不存在，就说明缺什么；不会为了表格齐全去伪造。

状态说明和样本的必需元数据

字段具体含义拟定规则
StateSpec.semantic / unit / tensor / frame_id / origin物理含义、单位、张量规格、表达坐标系、来源说明。保留；semantic 增加与新规范字段相应的细分含义。关节／开度不强塞一个世界坐标。

公共数值保持原生可表达精度；float32、float64 分别表示 32 位、64 位浮点数。六关节和七关节必须明确不同，不能补 0、截断或通过换名称“适配”。如要跨机器人重新规划关节运动，那是另一项能力，不是字段命名能解决的。

坐标、朝向与参考点

公共对象／字段统一约定边界
world当前具名环境协议的右手世界坐标。位置米、角度弧度、时间秒。不表示不同 Benchmark 的世界原点和朝向天然相同；轴向由各环境协议明确说明。
robot0/base被控机器人底座坐标；拟统一 x 向前、y 向左、z 向上。原生轴不同由环境 Adapter 转换。没有已核实底座姿态则不宣称已连通 world。
Pose.position_m / quaternion_xyzw / frame_id某个明确参考点的位置、方向及其表达坐标。xyzw 表示向量 x、y、z 在前，实数 w 在后。方向是该参考部件在 frame_id 中的朝向。位置和方向要属于同一刚性参考定义；不把原生四元数原样贴上 xyzw 标签。
Transform.translation_m / quaternion_xyzw把子坐标系中的点转换到父坐标系中的刚体变换。方向不能反着用；需要逆变换时显式计算，不猜。
FrameSpec.parent_id / static_transform / dynamic父坐标系／已知静态变换／关系是否随时间变化。未知时可以暂不连通；不能填零平移和单位旋转来假装已标定。
TimedTransform.transform / captured_at_s本次动态变换及它真正采集的时刻。必要路径缺失、太旧或来自未来均拒绝。图像不要求一定有全部相机外参，只有需要该变换的模型受此门禁约束。
site_id / control_site_id测量参考点／执行器动作目标参考点。控制参考点拟在末端声明中补充，不能把工具偏移藏进 Runner，也不能用名称相似代替已知变换。

例如：四元数从 wxyz 排成 xyzw，只是换分量顺序；把世界坐标转换成底座坐标，是改变表达坐标系；把手腕位置换成夹爪中心，是换工具参考点。这是三件不同的事，要分别有依据。

四元数必须有限、非零且符合声明的单位长度容差；不静默修成“看起来合法”。比较朝向时，整体取反仍算同一方向，例如 [0,0,0,1] 与 [0,0,0,-1] 都表示无旋转。具体数值容差在实现前作为转换测试参数明确记录，不靠放宽任务评分掩盖误差。

LIBERO 特别注意：现有位置 grip_site 和方向 right_hand 分别保留正确 site_id。匹配权重原来如何拼这两个输入，模型配置可继续按固定来源执行；但公共层不能因此声称它们已经是同一个通用工具位姿。

公共动作如何定义

先说明控制谁

target_id 是实际控制目标的公共身份，不是环境原生变量名。robot0 表示本轮唯一被控机器人实例，不是某个厂家型号。关节编号按说明书固定次序从 0 开始，不能按字符串自行猜物理关节。

机器人形式公共目标 ID具体含义
单臂robot0/eef、robot0/grip、robot0/j0 至实际最后一个关节单臂末端、夹爪、各机械臂关节。
双臂robot0/left_eef、robot0/right_eef、robot0/left_grip、robot0/right_grip分别明确左右末端和夹爪。
双臂关节robot0/left_j0 等、robot0/right_j0 等每个关节单独有 ID、单位、限位和来源；不能用一个含义不明的 14 维动作替代。

RobotSpec 保留 embodiment_id（真实机器人型号标签）、base_frame_id（底座坐标）、joints（关节说明）、end_effectors（末端说明）、grippers（夹爪说明）。JointSpec 保留 joint_type、position_unit、velocity_unit、effort_unit、position_limits；它们分别是关节类型、位置／速度／力的单位和位置限位。

EndEffectorSpec 保留 frame_id、tcp_id、gripper_id，拟新增明确的 control_site_id；分别说明部件坐标、工具参考点、关联夹爪和控制目标参考点。GripperSpec 保留 modes、max_width_m、joint_ids，即可用控制模式、已知最大宽度和夹爪关节身份。未知最大宽度时不得擅自推导“开度 → 米”。

每种命令说清楚做什么

所有命令都有 command_id / target_id / kind，分别是本条命令编号、控制目标、动作类型。一个 Action 的 commands 是一组同时提交的命令；它不是模型整段动作缓存，缓存仍归模型 Adapter。

类型专有字段和人话含义严格条件
joint_targetmode / value / unit：位置、速度或力矩模式；目标数值及单位。环境必须真有对应执行模式；关节目标不能靠坐标旋转变成另一台机器人的关节目标。
pose_targetpose：position_m、quaternion_xyzw、frame_id，表示到达哪个绝对物理位姿。控制参考点由目标声明确定；标准输出优先 world，其他已声明坐标由环境 Adapter 转换。
pose_deltadelta / frame_id / reference_policy / composition / reference_observation_id：移动多少、在哪个坐标中、相对哪次状态、从哪侧组合。chunk_start 指相对本段开始；step_observed 指相对本步测量；previous_command 指相对前一目标。pre/post_multiply 分别是从左／右复合变换；不能只写一个 dxyz 数组猜含义。
twist_commandtwist.linear_m_s / angular_rad_s / frame_id：线速度、角速度和表达坐标。可表达不等于已有真实执行器；原生不支持则拒绝。
gripper_commandmode / value：open_fraction 为 0 到 1 的目标开度；width_m 为米；joint_targets 为逐指关节目标；force_n 为牛顿。模式不可互换；转换必须有标定依据。原生“1 表示闭合”在环境边界明确反转。
controller_commandcontroller_profile_ref / parameters / parameter_domain：具名原生控制器、它的参数及“原生控制域”标识。只允许签名完全一致的原生协议。归一化 OSC 数组、旧双臂含糊编码、先插值后截断夹爪请求不能伪装成普通物理位姿或合法开度。

ActionSpec 继续声明 command_kinds、target_ids、controller_refs，即允许哪些动作类型、哪些目标、哪些原生控制器。ControllerSpec 的 frame_id、parameter_schema、parameter_units、parameter_domain 分别定义坐标、参数结构、单位和原生域。原生协议名称相同但参数含义不同仍不兼容。

坐标转换由双方 Adapter 调用共同的几何函数完成：环境负责原生 ↔ 公共；模型负责公共 ↔ 该权重训练编码。通用预检查只验证关系有依据；Runner 不做这些变换。

普通组合不再手填接线

普通 0.3 配置只选择 model、benchmark、episodes、budgets，分别表示模型、环境、运行回合和预算，并保留 run_id 与版本。输入按模型声明的公共路径读取，目标按公共目标 ID 匹配，坐标按已知坐标树与目标要求转换。

现有 BindingConfig 和 BoundProfile 继续供 0.2 使用。新通路拟生成只读匹配回执，记录实际公共输入、选定执行格式、坐标路径和警告；不是让用户继续手填这些内容。若有两个同样匹配但行为不同的执行格式，必须由具名环境 control_mode（控制方式选项）明确选择，不能取列表第一项。

特殊实验如故意改用侧视角，可以有显式覆盖，但它是改变实验输入，必须记录并重新核验，不是接入常态。第一个实现批次不需要先开发复杂的覆盖语言。

任务、预算、结果和证据

消息／字段组具体含义与要求
TaskSpec.task_id / episode_id / public任务、回合和公开目标。PublicTask 含 instruction、goal_image、goal_location，即任务文字、可选目标图和可选目标位置。模型只见 public。
initialization_ref / evaluation_config_ref / evaluation_private初始化依据、评分配置依据、私有评分参数。环境和证据可使用；私有字段不得进入模型。
budgets.env_steps / model_calls / tool_calls允许的原生动作数、模型请求数、工具调用数。缓存取下一动作也按原有请求／前向区别计数。
budgets.sim_time_s / wall_time_s仿真秒数预算／真实经过时间预算。变时长原生路径继续拒绝硬仿真时长上限；wall_time_s 只在调用边界协作检查，不是可中断的硬超时。
StepResult.observation / execution_feedback / terminated / truncated执行后的公开数据、实际执行回执、环境结束、预算等导致的截断。结束不等于任务成功。
ExecutionFeedback.request_id / call_id / command_ids对应哪条请求、可选工具调用及哪些具体命令。
status / code执行、部分执行、拒绝、规划失败或执行失败，以及相应错误码。状态未知不能伪造成完全执行。
consumed_env_steps / consumed_physics_steps / elapsed_sim_time_s本次实际消耗的原生动作次数、物理步数、仿真秒数。三者分别记录，不互相冒充。
ExecutionStatistics.env_steps / physics_steps / sim_time_s / model_calls / tool_calls / model_forward_count整局累计计数；未知的内部前向次数、无法确认的物理步数不编造。
Metric.value / unit / source / valid / unavailable_reason指标数值、单位、官方或声明的来源、是否有效、缺失原因。没评分器是 null 且无效，不是假装失败，也不是自造评分。
运行证据清单记录双方版本、权重／统计身份、环境协议、完整公共字段声明、实际解析结果、转换来源、资产与服务身份核验、计数、错误和真实／合成标记。

维持三种状态分开报告：结构可组合表示字段和执行接口满足；资产就绪表示固定文件及依赖通过核验；真实验证表示指定任务、起点、预算下实际运行。真实验证也不自动表示任务成功或全套 Benchmark 覆盖。

现有服务尚无可信权重身份回执，server_identity_verified=false 仍保留；本地权重摘要通过不能代替远端实际加载身份。DreamZero 待后续两张每卡 80GB H100 的真实动作验证；LingBot-VA 继续后置。本次公共字段方案不关闭这些外部缺口。

确认后按什么顺序推进

  1. 先锁定这份字段评审。确认公共命名、实测／目标、坐标与新版本兼容策略。此时只是在确认接口方案，不是正式冻结契约或阶段验收。
  2. 先做公共声明与预检查。新增独立版本类型、规范键校验、身份和参考点校验、公开路径读取与确定性执行格式解析。保留旧版本分发；不改控制器或评分。
  3. 先环境、再模型，各改一次。五个环境在边界产出规范字段；十一份模型规则读规范字段并保留内部编码。原生来源名只进入追溯元数据。
  4. 离线对照所有已迁移输入输出。先确认同一份原始图和状态进入模型前完全符合旧权重规则，原生动作经公共层来回后位置、方向、夹爪与精度不变，再启动真实推理。
  5. 集中有限步真实对照。先已就绪链路，再安排后置硬件。分别报告映射、重新推理差异、规划／执行差异和任务成功；不拿成功率替代映射核验。
  6. 交接与后续覆盖。更新接入指引、示例、覆盖账本和证据报告。全任务、多起点、预算与评分扩展按既有覆盖评审另行确认，不因这次改名自动扩大评测协议。

新增第三个组件时，只需要新组件自己的 Adapter、来源说明、具名规则和测试。无需修改 Runner，也无需改已有另一侧 Adapter。复杂机器人差异仍可能需要工作，但不能再通过每个组合额外写 Python 代码隐藏这些差异。
