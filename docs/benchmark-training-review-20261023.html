微调与零样本评测调研

核查日期：2026年10月23日（北京时间）。范围：当前注册的五类机器人仿真环境，官方论文／文档，以及本项目具名权重和固定源码。不是全部具身 Benchmark 的行业普查。

先回答有多少

你的观察基本正确。按我们接入的动作策略主要评测路线统计，五类中有四类采用“先用该 Benchmark 的训练数据训练／微调，再测试”的常见设置；一类 DROID sim_evals 明确按“不另用仿真数据训练，直接部署真实 DROID 策略”设计。但这不是“四类强制微调、一类模型从未训练”的二选一。
已接入环境主要路线如何评测零样本的边界
LIBERO训练／微调后测试。原始研究为终身学习和模仿学习；我们使用的 π0.5／OpenWAM 也是下游权重。新起点或知识迁移不等于整个 Benchmark 从未用于训练。固定版官方说明
VLABench我们接入的是动作模型路线，常规做法是微调后评测。官方另有零样本智能体工作流；不能把那条路线算成我们已经接入。论文 §4.1／§4.2／§9.1
RoboTwin 2.0论文仿真主实验用任务示范训练，再在干净／随机化场景测试。随机化场景未见、指令未见，不等于没用 RoboTwin 训练数据。论文 §4.5
RoboDojo（仿真）有明确训练集，官方策略采用训练／微调后评测。Open 类任务不提供对应示范，用来测学过其他任务后的新任务泛化。论文 §3.1.2／附录 K
DROID sim_evals真实 DROID 数据上训练的策略，直接进入三场景仿真；不要求另做仿真训练。这是相对目标仿真环境的迁移，不是“没用 DROID 数据训练”。当前来源没有官方任务成功评分器。固定版原生说明

因此可以记为“4 类有常规训练后评测路线，1 类以免仿真训练的迁移为设计目标”。前四类并非禁止拿冻结模型直接跑；只是那样测的是另一种能力，不能直接冒充原论文同条件复现。VLABench、RoboDojo 含有不同性质的路线／子任务，所以不把这组数字包装成互斥的永久标签。

如果问题换成“我们已经严格证明多少类环境及测试任务完全没有出现在模型任何阶段的训练数据里”，目前不能确认任何一类完成了这种全量排查。这是训练来源证据不完整，不是说零样本迁移不可能，也不是说已有动作没有运行过。

先把几种“没训练”分开

这里的“权重”就是模型训练后保存的参数文件；“微调”是在已有参数基础上，用目标数据继续训练。Benchmark 提供的是环境、任务和评测规则，通常不会因为你没有微调就禁止调用它。

说法人话解释能否直接叫整个 Benchmark 零样本
本项目没有训练下载别人训练好的权重直接评测。不能。别人可能已经用目标 Benchmark 训练过。
新场景／新物体／新指令同类技能学过，换摆放、外观或说法后还能不能做。不能扩大成整个环境从未见过。
新任务零样本不提供这项新任务的示范，看能否组合已学技能完成。只能说明指定任务未用于适配，其他训练任务可能来自同一 Benchmark。
不使用目标 Benchmark 数据适配拿冻结模型直接测，不用该 Benchmark 的示范更新参数。还要排查预训练是否已包含相关数据；未公开完整清单时标“未核实”，不能猜。
新机器人零样本连机器人的关节结构、动作接口或身体也换了。是更强、不同的问题；公共格式接得上不等于模型已经学会控制新身体。

这些区别也是本次统计的口径，不是新增公共契约字段。本报告没有改变模型训练、控制器或评测协议。

逐个 Benchmark 说明

LIBERO：原本就不是单纯的“拿来就考”

原始 LIBERO 研究机器人如何持续学习、迁移已有知识；官方提供示范数据、训练算法及训练后的评测入口。LIBERO-90 与 LIBERO-10 的划分，不能简单解释成“在前90项训练后，后10项一律禁止学习”：原始说明将后者用于下游终身学习研究。实际要看具体实验是否继续适配。固定版 README、官方训练／评测说明。

对我们当前配置，结论更直接：OpenPI 明确把 pi05_libero列在微调模型中；OpenWAM 对应模型卡也明确写明在 LIBERO 仿真基准上微调。因此，用这些现成权重不需要我们再训练一次，但不能称为“基础模型未接触 LIBERO 的零样本”。固定版 OpenPI 权重说明、OpenWAM 模型卡。

VLABench：确实有两种不同的考法

官方论文动作模型实验，会先微调 OpenVLA、Octo、RDT 等，再考察物体、语言和任务泛化；另有 VoxPoser、CoPA 一类不追加模型训练的智能体工作流。后者还包含感知、技能调用和规划模块，不能等同于同一个动作模型“只换 Adapter”。论文 §4.1、§4.2、§9.1、官方项目页。

我们采用 OpenWAM-VLABench 和 pi05-primitive-10task动作策略，不是上述零样本智能体系统。尤其 π0.5 的固定版模型卡明确说明：10项任务、5000段数据、8张H100、3万次训练迭代。轨道里“未见类别／纹理／指令”是在这种适配后继续测泛化，不能改名为整个 Benchmark 的零样本。匹配权重的固定版说明。

本项目当前仍限 track_1_in_distribution / select_fruit / trial0。配置中的 frozen-track1表示固定场景协议，不表示模型从未训练过。OpenWAM 本地发布配置指向 VLABench 训练数据；本轮远端对应模型卡未成功读取，不把这个缺口隐藏成完整训练清单已核验。

RoboTwin：场景变了，不代表任务没学过

RoboTwin 2.0 论文主仿真实验，每项任务用50段干净专家示范训练，在干净和强随机化条件下分别做100次测试。论文另有“零样本仿真到真实”实验，含义是用仿真数据训练后，不再用真实示范适配；不能解释为没有训练。论文 §4.4／§4.5。

当前 OpenWAM RoboTwin-Full与 LingBot-VLA 的 RoboTwin 版本都是下游训练权重。前者 Full 使用干净加随机化数据，不能拿它冒充“只用干净数据训练、测试随机场景”的 Clean2Random 设置。后者固定源码明确给出50任务、干净加随机化数据的后训练示例。固定版 OpenWAM 两种设置、固定版 LingBot 后训练说明。

我们配置的 instruction_type: unseen只限定指令来源，不证明该任务、机器人和物体从未用于训练。另两条把 RoboDojo 的 ARX 权重接入 RoboTwin 的记录属于跨来源部署尝试；没有完整训练排查与任务统计，不能仅凭更换环境就认定严格零样本成功。

RoboDojo：训练后测熟悉任务，也测没教过的新任务

仿真论文提供3500段训练轨迹，包含34项训练任务与一个辅助数据目录；Open 维度不提供对应任务示范。官方 π0.5 仿真实验从基础权重微调6万步。所以它有训练后评测路线，同时保留新任务泛化考法。论文 §3.1.2、附录 D／K。

官方仓库称当前发布为 eval-only，说的是“这个代码仓库负责评测端，不负责策略训练端”，不是“所有参加模型必须从未微调”。仓库本身也链接训练数据下载说明。官方仓库。

我们采用已发布的 ARX π0.5 检查点，以及明确在 RoboDojo 仿真轨道微调的 OpenWAM 权重。当前仅验证 stack_bowls及选定布局，不能把 Open 类未见任务的设计当成本项目已经完成该类评测。OpenWAM 权重来源。

DROID sim_evals：免仿真微调，不是免 DROID 训练

这个固定版小型 Isaac Sim 环境的 README 明确说明：仿真经过调节，以便真实 DROID 数据上训练的策略零样本运行，不要求另采仿真数据。它还明确偏向关节位置动作，不是任意策略和控制模式都可直接替换。固定版原生说明。

本项目接入的是这个三场景模拟器，不是把完整 DROID 真实世界数据集接成了统一成功率 Benchmark，也不是完整 RoboLab。借用 RoboLab 客户端处理组件，不会改变实际执行环境的身份。

DreamZero 固定模型卡明确声明其机器人训练数据来自 DROID。Cosmos 固定源码的后训练文档也将 Nano 基础模型在 Cosmos3-DROID 数据上后训练，作为 Policy-DROID 的复现配方。两者都不是“从未学习 DROID 机器人”的模型。前者仍等待后续双H100真实动作验证，后者已有有限步记录；设计宣称不等于本项目已完成全部场景的零样本成功率证明。DreamZero 固定模型卡、Cosmos 固定源码文档。

限制也必须保留：仿真本身经过调节，不是完全未经设计干预的环境；当前原生来源没有官方任务成功评分器。因此我们能研究迁移和执行，却不能自造一个 success 分数后说复现了官方全套成绩。此判断来自本地固定源码及项目评分声明，详见证据清单。

对我们的框架意味着什么

不推翻当前“每个模型一个 Adapter、每个环境一个 Adapter”的架构。Adapter 负责把已有观测和动作正确转换；训练负责让权重学会从观测做决策。换成公共字段不能凭空教会一个没学过的动作技能，任务失败也不能单凭现象判为 Adapter 错误。

因此，接入新模型／环境时有两个独立问题：一是图像、状态、坐标、动作和采样语义是否接得上；二是这份权重有没有相应机器人／技能能力。前者由 Adapter 和接口验证解决，后者需要合适现成权重、零样本实验或独立训练方案验证。微调通常产生另一份具名检查点，不意味着要为每个模型与环境组合重写 Python Adapter。

后续评测建议分两路记账，而不是把成绩混起来：

  • 训练后评测：明确使用过哪些目标训练数据、多少示范、训练预算、权重版本，再在指定测试条件下比较。
  • 冻结模型迁移：不追加目标数据训练；如实登记既有训练来源、未见维度和排查缺口。来源不完整就写未核实，不把“我们没训练”写成“从未见过”。

如果要正式比较“谁微调更省数据”，需要另行确定同等示范量、训练预算和测试集合；那是新增实验方案，不是本次只读调研已经授权开始训练。也不应把训练过程塞进通用 Runner。
