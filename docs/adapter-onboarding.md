# 模型和仿真环境接入指引

本指引面向需要新增或维护 Adapter 的开发者。目标是让模型只维护自己的输入输出，仿真环境只维护自己的观测、执行和评分；新增一方不逐个修改另一方，也不修改通用 Runner。Runner 指负责调用顺序、预算、计数和保存证据的执行循环。

当前采用已批准实施、尚未冻结的0.3契约。只接直接输出机器人动作的模型及仿真 Benchmark；纯视频、图片或文字输出不通过占位 Adapter 冒充机器人策略。新增协议或公共契约变化先提交具体含义和影响，再实施。

## 当前源码放在哪里

| 目录 | 新接入时如何使用 |
| --- | --- |
| `embodied_eval/v03/` | 当前公共协议、双方公共字段转换、独立注册和通用Runner；新Adapter遵循这里的接口 |
| `embodied_eval/core/` | 直接复用位姿、图像数组、类型化动作、物理校验、坐标路径和注册容器；不从历史契约导入基础类型 |
| `embodied_eval/native/` | 已有组件的原生输入输出处理、缓存、执行封装、资产清单与核验；不是新增模型必须使用的中间层 |
| `embodied_eval/adapters/` | 部分仍在使用的环境加载器、控制器工具及历史参考；引用前先核实职责，不直接复用旧组合工厂 |
| `embodied_eval/mn/`、`_legacy_*` | 历史测试和导入兼容；新Adapter不要向这些位置新增实现 |

新组件可以直接实现0.3接口，不必先实现旧消息再套一层。已有原生组件暂留的私有消息转换，仅用于保住已核验的输入编码、精度和执行行为，不是每个新接入都要额外填写的配置。

## 接入前先准备什么

模型侧固定源码提交、权重发布版本、匹配的归一化统计、原生输入示例和输出示例。归一化统计是训练权重匹配的数值缩放规则，不是任意一份同名文件。核实模型实际需要的图像、状态、动作含义、采样设置和连续动作缓存行为。

环境侧固定源码提交、任务或场景、初始化方式、随机种子、机器人、控制器、物理周期和官方评分入口。种子相同不保证不同初始化条目相同，因此同时记录具体初始状态或场景编号。先证明原生环境可以正常初始化及执行，不把依赖安装成功当作运行成功。

使用独立原生环境，不沿用 Mac 虚拟环境，不修改只读上游或相邻 XPolicyLab 项目。大文件下载只对当前命令临时移除代理后尝试直连，失败再回退；不改全局代理，不保存 API 密钥。

## 职责如何划分

| 部分 | 必须负责 | 不应负责 |
| --- | --- | --- |
| Model Adapter | 公共观测到模型输入；图像处理、状态排列、归一化、推理调用、动作解码、原生缓存和采样顺序 | 访问环境对象、按 Benchmark 名称分支、官方评分、替环境执行机器人控制 |
| Benchmark Adapter | 原生观测到公共观测；公共动作到控制器输入；坐标标定、机器人控制、逆运动学、物理推进、官方评分 | 按模型名称选择控制方式、模型图像处理、模型归一化、读取模型私有配置 |
| 公共几何工具 | 按明确提供的变换关系执行坐标或旋转表示转换，供 Adapter 调用 | 猜测原点、工具参考点或不同机器人之间的对应关系 |
| 注册和预检查 | 检查双方实际结构、输入、单位、坐标、动作和目标是否满足 | 用训练机器人名称当硬门槛，或用模型和环境组合白名单代替结构检查 |
| Runner | 生命周期、通用校验、预算、计数和证据保存 | 图像缩放、动作解码、归一化、机器人控制器、逆运动学或专属评分 |

逆运动学指根据末端位置和朝向求关节目标。训练覆盖未核实可以提示，但不自动拒绝；缺少必要输入、动作维数或物理含义不明则拒绝，不造数据补齐。

## 先把公共数据的含义写清楚

### 图像和状态

相机声明 RGB 等模态、用途角色、安装位置、坐标系、形状、数值类型和采集时间。RGB 指红绿蓝三个颜色通道。模型内部需要的缩放和排列放在 Model Adapter，不要求所有环境先输出同一种模型分辨率。

状态同时声明含义、单位、坐标系、数据来自哪个实际部位，以及是实测值还是控制目标。例如“当前关节角”和“上一次设置的关节驱动目标”不是同一字段。刚测量的关节和较旧的图像可以有不同采集时间，不能为了数字一致而篡改时间或多取图。

### 图像时间间隔与历史输入

0.3的可选 `observation-timing@1` 扩展只做观测时间对齐，具体字段与限制见[当前契约](contract-v0.3.md#可选观测时间扩展observation-timing1)。新增模型先核实匹配权重要求的是当前单帧、真实历史序列，还是服务内部保留的历史；不要把多相机维度当成时间维度，也不要把生成视频的帧间隔当作在线相机取图周期。

需要历史时，Model Adapter通过每个 `InputSpec.history` 声明秒数偏移、匹配策略、容差、起步是否接受较短历史及来源；公共 `ObservationHistory` 负责统一选择真实历史，模型再读取 `ModelInput.history[公共路径]` 编码，不按环境名称分支。新Model Adapter的单元测试必须证明历史真的参与输入，而不是收到后丢弃。

Benchmark Adapter用 `SpaceSpec.sample_timing` 声明真实公开采集能力，采集时间沿用原样。相机名义帧率、物理周期、环境控制周期、模型收到图像的时刻不能互相代替。不能为凑历史额外调用get_obs或推进仿真；只有原生接口能提供的样本才可以放进历史。不同传感器和状态可以各有时间要求。

运行配置显式选择 `temporal.mode=observation_aligned`。缺时间来源、非整数网格要求精确匹配、未授权的近似、起步固定历史不足都必须先拒绝。运行中再检查未来帧、实际周期、缺帧、重复采集、完整左右视角和容量；不额外调用模型、不重发动作、不自动恢复。

当前现有原生模型配置仍使用其当前画面接口和原生缓存；旧配置无需新增逐对配置。观测历史对齐不代表已经统一动作时间或推理频率；后两者本轮没有实现。近似实验、原生对照、真实推理和任务评分分别记账。

### 位姿和动作

公共位置使用米，关节转角使用弧度，时间使用秒。公共方向四元数使用 `xyzw`，即向量分量x、y、z在前，实数分量w在后；原生 `wxyz` 则把w放在前面。排列转换不等于坐标系转换，更不等于更换末端工具参考点。

位置、方向必须带明确坐标系及参考部位。环境 Adapter 提供机器人基座、世界和工具等坐标关系；模型 Adapter 将公共数据变成匹配权重实际需要的表达，并将输出还原为公共动作。已有工具见 [`transforms.py`](../embodied_eval/v03/transforms.py)。缺少真实变换关系时明确拒绝，不按名字或函数注释猜。

动作按实际含义选择关节目标、绝对位姿、相对位姿、夹爪或具名控制器命令。环境只接受自己真正实现的类型。双臂动作必须完整，不能静默丢弃另一只手、关节或夹爪。模型内部55维、80维等排列留在模型边界，不进入公共协议。

原生数组仅在双方声明相同具名协议和结构签名时可使用。特殊夹爪“先插值再逐步截断”的请求不能提前变成已经截断的公共开度；数值转换必须按固定原生来源核验。

### 0.3公共命名与自动匹配

0.3不再接受用户手写的 `binding`（逐对字段对应配置）。环境Adapter把原生字段先变成公共 `head/wrist/left_wrist/right_wrist` 等字段；模型Adapter从同一公共键取数据，再处理自己的输入私有命名。模型声明 `InputSpec.public_path`（例如 `sensors.head`）及输出公共目标，预检查依据实际结构自动产生 `ResolvedProfile` 匹配回执。回执记录选择结果，不是再让用户接线。

`head` 指工作区总览角色，不保证物理装在头部。`views.main` 只能使用环境明确声明的 `view_aliases.main`；缺必要视角不能猜一个补上。DROID两台外部相机暂用稳定的 `external_0/1` 来源编号；各权重的原生相机顺序由各自具名输入输出配置处理，不凭模型变量名判物理左右。

公共状态分清实测、控制目标、左右臂关节顺序和工具参考点。坐标或工具偏移无依据时拒绝，不用统一命名掩盖未知含义。完整字段与配置迁移说明见[0.3契约](contract-v0.3.md)。

现有配置示例见 [`mn_synthetic_run.json`](../examples/mn_synthetic_run.json) 和 [`mn_openwam_dual_wxyz_encoded_absolute.json`](../examples/mn_openwam_dual_wxyz_encoded_absolute.json)。后者是旧 OpenWAM 双臂权重的具名编码配置，不是所有 OpenWAM 权重的通用配置。

## 新模型需要实现什么

接口定义在 [`v03/interfaces.py`](../embodied_eval/v03/interfaces.py)。按下面顺序实现，不先改 Runner。

1. 定义自己的选项校验、来源记录和资产校验。未知字段、缺权重、版本或摘要不符要明确报错。
2. 提供 `CapabilitySpec`，即能力说明，声明所需观测、单位、维数、坐标、输出动作、完整目标及支持的时间模式。
3. 实现下表生命周期。模型只接收公开观测、公开任务和空间描述，不接收环境对象或私有评分条件。
4. 分别实现公共观测到原生输入、原生输出到公共动作。先验证这两个转换，再运行完整推理。
5. 注册自己的组件，不修改已有 Benchmark Adapter。

| 方法 | 要做的事 |
| --- | --- |
| `begin_episode` | 接收本次公开任务、空间与对应关系，清空上一轮缓存并执行原生要求的重置 |
| `observe` | 接收公开输入，保留观测编号及采集时间；需要坐标转换时调用公共工具 |
| `predict` | 按原生顺序调用推理或取缓存；返回公共动作，并关联本次请求和来源观测 |
| `end_episode` | 清理本轮缓存与状态，不让动作流入下一轮 |
| `close` | 关闭连接及自己拥有的资源；不终止不明外部进程 |
| `diagnostics` | 返回可核验的调用、缓存和来源信息，不输出密钥或完整进程环境 |

连续动作段通常称为 chunk，表示模型一次返回的多条顺序动作。缓存、取图节奏和动作段长度必须匹配原生实现。服务请求次数不等于真实模型前向次数；无法核实前向次数时保留未知值。

## 新环境需要实现什么

1. 定义环境自己的选项、源码、场景资产及协议身份，列出可选任务、初始化条目和控制方式。
2. 提供 `SpaceSpec`，即公共空间说明，包括机器人、坐标树、相机、状态、动作、控制器及完整目标要求。
3. 保留官方初始化和评分，不把专家动作或私有成功条件投影给模型。
4. 实现下表生命周期，独立验证观测转换、动作转换及真实执行计数。
5. 注册环境及指标模板，不修改已有 Model Adapter。

| 方法 | 要做的事 |
| --- | --- |
| `describe` | 返回实际公共空间；运行实例可核实原生物理周期，但注册时的静态描述不得启动仿真 |
| `enumerate_tasks` | 为选定轮次生成稳定任务标识、公开文字、私有初始化和评分引用；不得偷偷换任务或初始状态 |
| `reset` | 原生初始化后输出公共观测；动作和计时从约定起点开始 |
| `advance` | 将公共动作转为原生控制，执行并返回已确认的动作数、物理步数、仿真时间和反馈 |
| `score` | 调用官方评分；不存在或失败时返回无效／不可用指标，不伪造成功或失败 |
| `close` | 核实本组件拥有的仿真或子进程收尾情况 |
| `diagnostics` | 保存初始化身份、实际计数、协议及安全失败信息 |

`fixed_period` 表示每条动作固定周期；`measured_native` 表示一条原生动作可能推进不同数量的物理步。后者分别记录原生动作次数、实际物理步数和仿真秒数，不用一个固定乘数推算；当前拒绝硬仿真时间上限。

动作部分执行或状态未知时，反馈必须如实说明。不能把规划失败后只动了夹爪的结果记为完整双臂动作成功，也不能擅自重发可能已执行的动作。通用硬超时、恢复和并行评测尚未实现。

## 如何注册并让命令行找到组件

注册结构见 [`v03/registry.py`](../embodied_eval/v03/registry.py)。模型注册需要能力描述、工厂、选项校验、资产核验、就绪检查和来源记录；环境额外提供指标模板。工厂指运行时创建 Adapter 实例的函数，不是模型与环境的组合工厂。

建议在新组件模块中提供 `register(registry)` 函数，调用 `register_model` 或 `register_benchmark`，然后在 `default_registry()` 初始化时导入并调用该函数。只注册新增组件，不改另一方实现或 Runner。当前不会自动扫描外部安装包，因此只写一个类但不注册，命令行不会自动发现它。

注册模块及静态描述只依赖轻量元数据。Torch、JAX、NumPy及仿真库等原生依赖在运行工厂或方法中延迟导入，防止预检查抢先占用 GPU。就绪检查表示本地路径等条件；资产核验表示固定内容摘要；两者都不冒充实际服务已经加载权重。

隔离测试可创建自己的 `AdapterRegistry` 并传给 `check` 和 `run`；正式命令行配置校验使用默认注册表，所以接入命令行前必须登记到默认注册过程。

## 按什么顺序调试

### 先做结构和资产检查

以下命令均从项目根目录执行。`check` 检查声明和配置，不启动真实模型或仿真。

~~~sh
.venv/bin/python -m embodied_eval check --config examples/mn_synthetic_run.json
.venv/bin/python -m embodied_eval check --config examples/mn_openwam_dual_wxyz_encoded_absolute.json
~~~

对于自己的配置，把 `--config` 后的路径替换为实际配置文件。确认轻量检查通过后，再加 `--verify-assets` 检查已下载文件；它不下载、不启动推理，也不证明原生运行依赖已兼容。

检查结果分别看 `structurally_compatible`（结构满足）、`readiness`（本地准备情况）、`assets_verified`（资产核验）和 `real_validation`（预检查不做真实验证）。即使命令退出码为0，也不能因此宣布已完成真实接入。

### 再做保存数据的转换对照

同时保存原生观测、模型原生输入、原生输出和原生执行动作，验证下列项目：

- 相机原图、左右视角、图像排列及预处理顺序匹配原生路径。
- 状态排列、归一化统计、数值类型和精度符合匹配权重的要求。
- 原生动作转公共动作，再转执行端原生动作，保持实际物理含义。旋转比较允许四元数整体取反，因为它表示相同朝向。
- 左右臂、全部关节、夹爪及必要观测完整；缓存重置、动作消费和取图节奏不变。
- 坐标已知时正确转换，坐标或参考部位不明时明确拒绝。

现有合成测试可参考 [`test_v03_public_space.py`](../tests/test_v03_public_space.py)、[`test_mn_openwam_dual_pose.py`](../tests/test_mn_openwam_dual_pose.py) 和 [`test_robotwin_execution_audit.py`](../tests/test_robotwin_execution_audit.py)。合成测试是人工构造的接口检查，不是模型或任务成绩。

### 然后分别验证模型和环境

先让模型在明确的原生输入上返回一段合法动作，再让环境单独初始化和执行少量有来源的动作；两侧原生依赖分别固定。不要在模型还无法单独推理时，用闭环任务成功与否定位问题。

真实短跑必须使用已经确认的任务、初始化、控制器和预算，新建输出目录。采用旧短跑配置时，先核实服务端口、权重及原生环境；配置中有地址不表示该服务当前在线。模型内部变换、环境执行和任务成功分别检查。

### 最后做独立原生对照及完整任务

原生参考不能调用生产 Adapter 的转换来证明生产 Adapter 自己正确。先对齐实际输入和动作，再比较控制与执行；重新推理差异和官方任务结果单独报告。

RoboTwin 已发现相同已记录规划输入产生不同原生轨迹。固定已保存规划结果可以定位执行边界，但不能替代真实重新规划，不能自动豁免严格复现差异。

完整任务和多初始状态覆盖按[覆盖扩展评审](benchmark-coverage-review.md)推进；不把一个试点的完成写成整套 Benchmark 已完成。

## 常见失败按哪一层排查

| 现象 | 先检查 |
| --- | --- |
| 不认识新 Adapter | 默认注册是否调用了新组件注册函数；名称是否重复 |
| 缺相机、状态或动作不兼容 | 公共声明与实际输入是否匹配；双方声明的公共字段、坐标路径和完整目标是否满足，不要先改 Runner |
| 文件存在但核验失败 | 源码提交、权重、归一化统计、分片和摘要是否对应，不跳过校验 |
| 导入或 GPU 初始化失败 | 各自原生依赖、驱动、显存、许可证及离线资产；不是模型任务失败 |
| 相同输入产生不同动作 | 推理采样、随机状态、缓存、原生数值和调用顺序；单独保存差异 |
| 动作相同但观测不同 | 控制转换、原生规划结果、控制序列、物理状态和取图时点，逐层定位 |
| 运行完成但任务未成功 | 先确认映射与执行，再看官方任务结果；任务失败不自动说明 Adapter 出错 |

## 提交时需要哪些证据
